# ⚡ Руководство по подключению Supabase к Системе Аньянова

## Зачем нужен Supabase в проекте?
1. **Глобальный каталог ароматов (Global Perfume Registry):** любой флакон, добавленный пользователем, рассчитывается по формуле и становится доступен всем пользователям сервиса.
2. **Синхронизация полок (User Shelves):** личный парфюмерный гардероб синхронизируется между всеми устройствами пользователя (телефон, ноутбук).
3. **Аналитика поводов (Situation Logs):** сервер фиксирует, какие ситуации люди вводят в поиск, позволяя обогащать пресеты и выявлять тренды.
4. **Offline-First:** если проект запущен без ключей Supabase, он автоматически работает на 100% локально через `localStorage`.

## 🚀 Пошаговая настройка за 3 минуты

### Шаг 1. Создание проекта в Supabase
1. Перейдите на [supabase.com](https://supabase.com) и войдите через GitHub или Google.
2. Нажмите **«New Project»**, задайте имя (например, `system-anyanov`), выберите ближайший регион (например, `Frankfurt`) и сохраните пароль БД.

### Шаг 2. Создание таблиц (Запуск SQL миграции)
1. В левом меню консоли Supabase перейдите в раздел **SQL Editor**.
2. Откройте файл `supabase/migrations/20260920000000_init_anyanov_schema.sql` из проекта.
3. Скопируйте всё содержимое файла, вставьте в поле SQL Editor и нажмите зеленую кнопку **«Run»**.
4. Все таблицы (`fragrances`, `user_shelves`, `situation_logs`), индексы и правила безопасности (RLS) создадутся мгновенно.

### Шаг 3. Подключение API ключей в проект
1. В консоли Supabase перейдите в **Project Settings -> API** (или **Project Settings -> Data API**).
2. Скопируйте два значения:
   * **Project URL** (например, `https://abcdefghijk.supabase.co`)
   * **Project API Keys -> `anon` / `public`** (публичный anon-ключ)
3. Создайте файл `.env.local` в корне проекта (или укажите переменные в Vercel/Netlify):
```bash
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key_here
```
4. Перезапустите dev-сервер:
```bash
npm run dev
```

## 🔒 Безопасность (Row Level Security)
* Таблица `fragrances`: читать могут все посетители сайта; добавлять новые ароматы могут все (краудсорсинг).
* Таблица `user_shelves`: защищена для каждого конкретного клиента.
* Никаких секретных ключей (`service_role`) в клиентском коде не используется!
